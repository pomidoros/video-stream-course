# Контракты решения

Реализуйте только заготовки; `project/`, оценщики и тесты предоставлены. Их изменение не влияет на преподавательскую проверку. Индексы кадров 0-based; время в секундах, координаты в пикселях исходного кадра. Инференс использует только текущий и предыдущие шаги. Тест на префиксе проверяет, что будущее не меняет прошлые выходы.

## Мяч: shots/outcome_student.py

`track_ball(detections, rim)` получает хронологический список `(frame, time_s, detections)` и кольцо `xyxy`. Каждая детекция — `{class_name, confidence, box: np.ndarray[4]}`. Временной шаг берите из времени, а не номера строки. Возврат: список той же длины, каждый элемент `{frame, time_s, observed: bool, x, y, vx, vy}`. При отсутствии состояния все четыре координаты/скорости `None`. При прогнозе без наблюдения `observed=False`. Дополнительные поля разрешены. Вход не изменяйте.

`find_candidates(tracks, rim)` возвращает строго возрастающие фактически наблюдавшиеся времена кандидатов. Для базового задания линия подлёта — `rim_y1 - 0.5 * rim_width`; пересечение сверху вниз, горизонтально в пределах `1.5 * rim_width` от центра; подавление повторов 1.2 с. Не интерполируйте время назад. Детекции мяча и признаки сети имеют разные временные сетки: кандидат может находиться между кадрами 70-мерного кеша. Готовая очередь ждёт 1.8 с и выбирает следующий доступный кадр признаков.

`build_training_windows(features, time_s, attempts, length)` → `(X, y)` float32 с формами `[N,length,D]`, `[N]`. Концы окон рассматриваются в порядке `range(length-1, len(features), 2)`. Известная метка применима, если конец попал в `[reference_time_s+0.8, reference_time_s+1.8]`; `made=1`, `missed=0`, `uncertain` не создаёт обучающую метку. Окно заканчивается текущим индексом включительно. Без примеров вернуть пустые массивы форм `[0,length,D]`, `[0]`. В предоставленных данных интервалы разных попыток не конфликтуют.

`TemporalOutcomeModel(kind)` — `torch.nn.Module`, `kind` один из `last`, `mean`, `gru`. На вход `[B,T,70]`, на выход конечные logits `[B]`, без sigmoid. Last использует последний кадр, mean — усреднение, gru — временную модель. Готовый `FrameBaseline` можно использовать для last. Требуется сопоставимая ёмкость моделей, ориентир проекция 70→32, hidden32.

`train_model(model, (tx,ty), (vx,vy), config)` обучает переданную модель **на CPU**, восстанавливает лучшие веса по validation Brier и возвращает `{curve: [{epoch, train_loss, validation_brier}], best_epoch}`. `config` содержит `epochs`, `lr`, `seed`; допускаются дополнительные настройки. Начальная рекомендуемая конфигурация: AdamW, lr=.001, BCEWithLogitsLoss, до120 эпох, early stopping20, batch64. Возвращать необученную модель недопустимо. Готовый runner сам сохраняет `state_dict`, seed, фактическое изменение весов, историю и train-only scaler.

## Люди: players/people_student.py

`cosine_distances(queries, gallery)` → матрица `[Q,G]` расстояний в `[0,2]`. Нормализуйте ненулевые входные векторы; не изменяйте их. Неверный rank/размерность, нулевой вектор, NaN/Inf → `ValueError`. Пустые Q/G допустимы, форма выхода сохраняется.

`identify_people(queries, gallery, gallery_ids, threshold=.3)` → integer array `[Q]`: ID ближайшего образца при расстоянии ≤ threshold, иначе `-1`. При равенстве выбирайте первый образец. При пустой gallery всё `-1`. Метки query не передаются. Подготовка непересекающихся gallery/query и их оценка предоставлены в `project/retrieval.py`; метки GT нужны только для этого отдельного retrieval-эксперимента, не для трекера.

`track_with_deepsort(data, fps, max_age_s=1., cosine_threshold=.3)` получает только `frames`, `det_frame`, `bbox[N,4]` xyxy, `confidence[N]`, `embeddings[N,512]`. `fps` — частота исходного MP4. Шаг сетки получите по `frames` (в комплекте2; для единственного кадра примите2). Время жизни в шагах — `ceil(max_age_s*fps/stride)`. На каждом шаге выполняйте predict/update, в том числе при отсутствии детекций. Начальные параметры: cosine=0,3, budget=50, n_init=3, max_iou_distance=0,7.

Возврат — список на **каждый** frame:

```json
{"frame": 2, "time_s": 0.1001001, "tracks": [
  {"track_id": "1", "bbox": [20, 30, 80, 180], "confirmed": false,
   "observed": true, "missed_steps": 0, "detection_index": 7}
]}
```

`track_id` — положительное целое либо его строка; уникально в кадре. `detection_index` наблюдаемого трека ссылается на строку **переданного** кеша текущего кадра. Один detection нельзя назначить двум трекам. После фильтрации входа индексы относятся к отфильтрованному массиву. Библиотека позволяет сохранить индекс через `Detection(..., others=index)`.

`bbox=None` разрешён только для ненаблюдаемого трека без достоверной позиции. Если прогноз Kalman дал неположительную ширину/высоту, передайте `bbox=None`, а не некорректный прямоугольник. Не подменяйте его правильной разметкой. В scoring остаются все GT-объекты, поэтому потерянная позиция даёт FN. Подтверждённые предсказанные рамки участвуют в метриках.

Визуализатор поддерживает любые настоящие track ID и не перенумеровывает их ради красивой картинки.
