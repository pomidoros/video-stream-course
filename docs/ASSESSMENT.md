# Проверки и оценивание

Всего **50 баллов**, индивидуально, оценка нагрузки14–20 часов. Основная рубрика в ASSIGNMENT.md. Автоматические проверки дополняют проверку кода, обучения и анализа; они не заменяют её.

## Открытые проверки

`python scripts/check.py environment` проверяет файлы, SHA-256, split и зависимости. Не требует реализации решения.

`python scripts/check.py contracts` проверяет формы тензоров, градиенты, изменение весов, окна, неизвестные метки, cosine/unknown, временные сетки, пустые наблюдения и причинность. Тесты специально короткие. Не требуется выдавать те же произвольные ID, что у эталона. Начальные `NotImplementedError` должны стать проходящими реализациями.

`python scripts/check.py metrics --models artifacts` заново запускает сохранённые модели и трекер и вычисляет:

| Показатель | Открытый порог |
|---|---:|
| F1 событий полного потока | ≥0.85 |
| Найдены и правильно классифицированы известные броски | ≥0.65 |
| Доля известных бросков с найденным определённым ответом | ≥0.85 |
| Brier известных найденных определённых исходов | ≤0.30 |
| Macro-F1 исхода, оба класса | ≥0.60 |
| IDF1 игроков | ≥0.35 |
| Recall игроков | ≥0.75 |
| Re-ID top-1 известных query | ≥0.75 |

Исходы — validation-записи, модель `gru`, порог класса0.5. People — агрегат двух evaluation-клипов, GT IoU≥.5. IDF1 считается из общего MOT-аккумулятора, а не средним процентов. Retrieval — первая/последняя треть, средняя исключена. Open-set и стрессовые метрики публикуются в отчёте, но высокий результат на них не обязателен: текущие данные и baseline не дают для этого надёжного основания.

Пороги выбраны как проверка работоспособности базового решения с запасом, без требования повторить конкретное решение. Провал порога не обнуляет весь проект. Исправная реализация, собственное обучение, воспроизводимость и содержательный отрицательный результат оцениваются по своим разделам. Нет требования победить mean pooling с помощью GRU или геометрический baseline с помощью DeepSORT.

## Закрытая проверка: до5 баллов

Внутри последних8 баллов рубрики: **5 — закрытые метрики, 3 — итоговый отчёт, воспроизводимость и сложные случаи**. Остальные42 балла относятся к реализации и экспериментам. За каждый из первых пяти порогов таблицы —1 балл на закрытых записях бросков, без требования к скрытому people-бенчмарку. Неизвестные правильные исходы не участвуют в бинарной метрике. Пропущенная попытка или unknown снижает сквозную точность/coverage; лишний кандидат даёт FP.

Формулы и пороги открыты. Скрыты только записи и разметка. Код и веса фиксируются до теста, перенастройка после получения результата не допускается. Локальная validation мала; небольшие изменения метрик возможны. Закрытый результат возвращается после срока сдачи, не как неограниченный сервис для подбора параметров.

Преподаватель заново запускает ваше зафиксированное решение на входах без меток и отдельно считает метрики доверенным оценщиком. Скрытые файлы не кладутся в этот репозиторий, ветку или Actions Secrets. Прохождение студенческого workflow не доказывает итоговый балл, потому что студент может изменить свой workflow и тесты.

Метрики не являются полной защитой от списывания. Собственное обучение подтверждается кодом, кривыми, checkpoint, воспроизведением и обсуждением решения, а не только наличием `.pt`.
