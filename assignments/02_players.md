# Часть 2. Игроки и Re-ID

Реализация: [players/people_student.py](../players/people_student.py). **10 из 50 баллов**, ориентир 5–6 часов. Используйте `deep-sort-realtime` с готовыми признаками внешности; обучение детектора и OSNet не требуется.

## Данные

В `players/videos/` — три игровых MP4. В `players/data/` — детекции, признаки OSNet, разметка для оценки и результаты геометрического baseline. Исходные видео имеют частоту 19,98 FPS, кеш — 9,99 FPS. Разделение development/evaluation задано в manifest.

ID локальны внутри записи. Один и тот же номер в разных видео не означает одного человека. Целевые объекты — игроки на площадке; детектор может находить и других людей.

## Что реализовать

1. **`track_with_iou`** — собственный трекер по пересечению рамок: сопоставление один-к-одному, новые треки, пропуски и удаление устаревших. Готовый DeepSORT внутри этой функции использовать нельзя.
2. **`cosine_distances`** — расстояния между признаками запросов и образцов.
3. **`identify_people`** — ближайший образец из gallery или `unknown`, если сходства недостаточно.
4. **`track_with_deepsort`** — адаптер трекера к детекциям и внешним признакам. Обрабатывайте каждый шаг, включая шаги без детекций. Форматы и начальные параметры — в [API](../docs/API.md).

5. **`player_statistics`** — время наблюдения, путь, средняя и максимальная скорость в пикселях/с, карта посещений для каждого ID. Не соединяйте точки через потерянные наблюдения.

## Что исследовать

- Сравните DeepSORT со своим IoU-трекером по IDF1, MOTA, сменам ID, FP и FN.
- Проверьте поведение при пропусках детекций. Оба ваших трекера запускаются на одинаковых входах. Готовый запуск убирает наблюдения на шагах `20 ≤ step % 45 < 25`, сохраняя течение времени.
- Оцените Re-ID: gallery строится из первой трети видео, query — из последней. Готовый протокол также исключает одну личность из gallery для контролируемой проверки `unknown`. Сообщите top-1, долю правильно принятых известных и ложные принятия неизвестных.
- Посмотрите видео результата, сформулируйте причину одной из ошибок и **проверьте одно своё улучшение**. Сравните до/после на тех же данных. Способ улучшения выберите сами.

Параметры выбирайте на development, затем фиксируйте для evaluation. Эталонная разметка используется только в оценке и отдельном retrieval-эксперименте. Трекер её не получает. Перенумеровывать предсказания по правильным ID нельзя.

В отчёте нужны таблица результатов, пример статистики и объяснение эксперимента. Объясните, как смена ID и пропуски искажают путь и тепловую карту; без калибровки не переводите результат в метры. Рост всех метрик не обязателен. Это малый учебный поднабор: его результаты нельзя выдавать за качество на любых игровых сценах.

Распределение 10 баллов: IoU-трекер — 2, DeepSORT — 3, Re-ID — 2, статистика — 2, собственный эксперимент — 1.

Старые файлы `*.geometry.stress*.json` в данных — дополнительный готовый метод с Калманом. Он отличается от вашего простого IoU-трекера и не заменяет его реализацию.

Тепловые карты и таблицы автоматически сохраняются в `outputs/people/`. Видео с рамками, подписями и карточками создаёт [готовый скрипт](../docs/VISUALIZATION.md).
