# Техническая памятка

[← Условие работы](assignment.md) · [Установка и первый запуск](../starter_kit/README.md)

Обращайтесь к этой памятке по ходу реализации: здесь собраны форматы, правила и команды.

## Данные

Во всех сценах видео имеет разрешение 640×360 и частоту 15 кадров/с. В debug — 120 кадров, development — 240, challenge — 300.

В каждой папке сцены находятся:

| Файл | Что содержит | Как используется |
|---|---|---|
| `video.mp4` | Изображения сцены | Фон для покадрового просмотра и итогового видео |
| `measurements.csv` | Доступные алгоритму прямоугольники | Вход вашего трекера |
| `seqinfo.yaml` | FPS, разрешение и число кадров | Готовое чтение видео и запись результата |
| `zones.json` | Контрольная линия, направление входа, начальная заполненность | Настройка счётчика |
| `expected_counts.json` | Контрольные числа входов и выходов для debug/development | Только оценщик; не вход трекера |
| `ground_truth.csv` | Правильные положения и ID людей | Только внешняя оценка; у challenge этого файла нет |

Например, одна из строк `debug/measurements.csv`:

```csv
frame,measurement_id,x,y,width,height,confidence
5,-1,114.945,42.139,27.888,59.494,0.888
```

Это одно обнаружение в **кадре № 5**: левый верхний угол `(x, y)`, ширина и высота прямоугольника в пикселях. `confidence` — уверенность имитируемого детектора. Номера кадров начинаются с **1**. В одном кадре может быть несколько строк или ни одной. `measurement_id` всегда `-1`: готовой личности человека в измерениях нет, ID назначает ваш трекер.

## Обработка одного кадра

Для каждого кадра готовый код в `main.py`:

1. Читает изображение из MP4 и измерения с тем же номером из CSV.
2. Передаёт измерения в ваш `MultiObjectTracker.step(...)`.
3. Получает список треков с ID, положениями и признаком «измерение / прогноз».
4. В отмеченном месте `TODO(student)` вы передаёте подтверждённые треки своему счётчику и записываете события входа/выхода.
5. Готовый визуализатор рисует результат на кадре, а готовая обвязка сохраняет видео и таблицы.

Например: объект наблюдался, затем его измерения пропали на несколько кадров. Нужно продолжить его трек по прогнозу. Если измерение вернулось до удаления трека, сопоставить его с прежним ID и уточнить положение. Если наблюдения подтверждают переход через линию — записать событие. Пересечение только по прогнозу событие не создаёт.

## Правила реализации

В `kalman.py` допишите `predict` и `update` для состояния `[cx, cy, vx, vy]`; инициализация уже дана. В трекере нужны сопоставление один-к-одному, отбрасывание слишком далёких пар, создание, подтверждение и удаление треков. Пустой кадр не должен останавливать обработку.

Трекер возвращает `list[TrackView]`: `track_id`, `bbox`, `center`, `source`, `confirmed`, `missed`, `recovered`. Поле `bbox` имеет формат `(x, y, width, height)`. `source="measurement"` означает, что трек обновлён текущим измерением; `source="prediction"` — что есть только прогноз. Счётчик получает центр подтверждённого трека и информацию о наличии измерения.

В выданной обвязке `dt=1.0`: единица времени фильтра — **один кадр**, скорости — в пикселях за кадр. FPS нужен для воспроизведения видео. Не меняйте единицу времени без согласованного изменения параметров фильтра.

В этом учебном счётчике одно и то же направление учитывается не более одного раза для одного `track_id`. Точка точно на линии не должна скрывать переход с одной стороны на другую.

Счётчик `current` равен `initial_occupancy + entered - exited`: это баланс пересечений относительно заданного начального значения, а не число фигур, видимых в кадре. Отрицательное значение нужно разобрать в отчёте, а не скрывать обрезанием до нуля.

Чтение CSV/видео, отрисовка, запись файлов, оценщик и браузерная оболочка уже готовы. Готовые SORT, DeepSORT, фильтры Калмана и Re-ID использовать нельзя. Для венгерского назначения разрешён `scipy.optimize.linear_sum_assignment`.

Контрольная линия задана в `zones.json`: сверху вниз — вход, снизу вверх — выход. Проверяйте пересечение конечного отрезка, а не его бесконечного продолжения.

## Запуск и просмотр результата

После распаковки рядом должны находиться `docs/`, `data/` и `starter_kit/`. Откройте терминал в этой общей папке и перейдите в `starter_kit`. Последующие команды выполняйте из неё:

```bash
cd starter_kit
python3 -m pip install -r requirements.txt
python3 -m pytest tests -q
```

**До реализации алгоритмов десять тестов падают с `NotImplementedError` — это ожидаемо.** Проверки выходных файлов пропускаются (`skipped`), пока соответствующая папка результатов не создана. Сначала допишите Калман, затем трекер, счётчик и блок в `main.py`. После этого:

```bash
python3 -m src.main --data ../data/debug --output results/debug --config configs/easy.yaml
python3 -m src.evaluate --data ../data/debug --results results/debug
```

Откройте **`results/debug/demo.mp4`**. Серые рамки — входные измерения, зелёные — треки с измерением (`M`), оранжевые — прогнозы (`P`), голубая линия — граница подсчёта. Внизу: `IN` — входы, `OUT` — выходы, `NOW` — текущий баланс, `RECOVERED` — число ID, восстановленных после пропуска.

Затем переходите к остальным сценам:

```bash
python3 -m src.main --data ../data/development --output results/development --config configs/medium.yaml
python3 -m src.evaluate --data ../data/development --results results/development
python3 -m src.main --data ../data/challenge --output results/challenge --config configs/hard.yaml
python3 -m pytest tests -q
```

Используйте готовые конфиги: `easy.yaml` для debug, `medium.yaml` для development и `hard.yaml` для challenge. **Менять их не обязательно, это не снижает оценку.** Если хотите исследовать настройку, делайте это только на debug/development и зафиксируйте конфиг challenge до запуска. Для challenge локальная оценка без закрытой разметки недоступна. Во время обработки трекер не должен читать `ground_truth.csv` или `expected_counts.json`.

## Эксперимент с пропусками

Готовый скрипт создаёт семь копий debug. Выполните из `starter_kit`:

```bash
python3 -m src.prepare_gaps --data ../data/debug --output ../data/gap_experiment
```

Появятся папки `gap_00`, `gap_05`, `gap_10`, `gap_15`, `gap_20`, `gap_25`, `gap_30`.
В каждом варианте удалены измерения всех объектов начиная с кадра 40 на указанное
число кадров: например, `gap_10` не содержит измерений кадров 40–49. Номера
оставшихся кадров не меняются. Видео, разметка и контрольные суммы скопированы
без изменений. В `gap_00` измерения полностью совпадают с исходными.
Исходная сцена не изменяется. Если каталог вариантов уже существует, используйте
его или укажите новый `--output`: скрипт не перезаписывает готовые файлы.

Обработайте все семь вариантов своим решением. Пример для `gap_10`:

```bash
python3 -m src.main --data ../data/gap_experiment/gap_10 --output results/gaps/gap_10 --config configs/easy.yaml
python3 -m src.evaluate --data ../data/gap_experiment/gap_10 --results results/gaps/gap_10
```

Для остальных вариантов замените `gap_10` в обеих командах. Запуски можно объединить
в небольшой цикл. На всех вариантах используйте **один и тот же код и неизменный
`configs/easy.yaml`**: меняется только длина пропуска, подбирать параметры не нужно.

Из каждого `metrics.json` возьмите `entry_count_error + exit_count_error`. Соберите
таблицу «длина пропуска, входы, выходы, суммарная ошибка» и постройте график
«длина пропуска → ошибка подсчёта». Объясните наблюдения по трекам и сроку их удаления.
Ошибка может расти, уменьшаться или оставаться одинаковой; все эти результаты
допустимы. Оцениваются корректность опыта и объяснение, а не форма графика.

## Интерактивный просмотр

Для интерактивного просмотра после получения результатов всех сцен выполните из `starter_kit`:

```bash
python3 -m src.export_dashboard --project .. --results-root results --output interactive/data.js
cd ..
python3 -m http.server 8000
```

Откройте `http://localhost:8000/starter_kit/interactive/`. Оболочка позволяет выбрать сцену и кадр, включить измерения, прогнозы, траектории и открытый GT. Для challenge GT недоступен. HTML/CSS/JS писать не требуется.
